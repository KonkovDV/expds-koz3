# Где именно E1_G1 и v4 теряют к v2: целые TP и FP по логам площадки (05.11.2026)

**Вопрос.** Чистая геофизика E1_G1 на LB дала 0,38988, на 0,0226 ниже v2 (0,41238), хотя честный OOF обещал полноту геофизики 0,674. Где разница в целых объектах? Что это значит для чистой линии и для финала?

Расчёт описательный, по трём уже сделанным посылкам. Новых посылок и подбора порогов нет.

## Данные и способ

- **Логи площадки** на одном и том же публичном тесте:
  - `docs/background/LB_SCORING_v2_eb268d6_0.41238.log`;
  - `docs/background/LB_SCORING_e1g1_ed51cae4_0.38988.log`;
  - `docs/background/LB_SCORING_v4c1f_f0def982_0.34418.log`.
- **Инструмент** — `scripts/lb_diff.py` (новый, тесты `tests/test_lb_diff.py`). Он восстанавливает целые TP, FP и эталоны по типам данных (как `scripts/lb_counts.py`). Лог v4 по FP ratio не сходится, пока у ортофото не допущены неизвестные ложные; их 2. Корзины площади инструмент сводит к самому мелкому эталону, общему для всех логов. Полный вывод — `lb_diff_v2_e1g1_v4.txt`, `.json`.
- **Точки в корзины площади не входят** (`compute_metrics`, `size_categories`; см. докстринг `scripts/lb_breakdown.py`). Поэтому изменение TP геофизики, которого не видно в корзинах, приходится на находки `finds_points`.
- **Состав геофизики публичного теста** — из файла структуры организаторов (`notes/public_val_2026-10-22.json`):
  - MagGr — **2 участка, по одному файлу**; одна маска шума;
  - EtGr — 1 участок: 4 карты (0,75 / 1,0 / 1,25 / 1,75 м) и 14 профилей;
  - TerFl — 1 файл.
- **Правило окупаемости.** Блок из a попаданий и b ложных повышает F1 типа (FP весит 0,5) тогда и только тогда, когда доля попаданий h = a/(a+b) больше F/(4−F) того прогона, к которому блок добавляют. Это точное условие, а не приближение (проверено в тестах на сетке значений).

## Выводы

1. **Геофизика E1_G1 теряет на находках двух карт MagGr.**
   - Против v2 у E1_G1 −378 TP и −400 FP геофизики. Сумма изменений по корзинам площади −12 TP, и из них −3 — спутник. Значит, почти вся потеря — точки, то есть находки `finds_points`.
   - На публичном тесте находки есть только на двух файлах MagGr.
   - Контур `object_poly` по TP-парам у E1_G1 стал плотнее (HD95 6,9 → 2,2 м, PoLiS 2,6 → 0,8 м): ORG3 на EtGr рисует полигоны точнее. Число TP в корзинах при этом почти то же.

2. **Рабочая точка E1_G1 на тестовых картах слишком осторожна.**
   - Выдачу, которой у E1_G1 нет, а у v2 есть, v2 попадает в **48,6 %** случаев. Безубыточность для E1_G1 — **15,7 %**. Точность геофизики E1_G1 0,872 против 0,769 у v2 говорит о том же: модель режет слишком много.
   - При этом E1_G1 лучше классики без оговорок. Против геофизики v4 (это уровень v3a_min) у неё +120 TP и −188 FP.
   - Модель находок работает. Не переносится на тест её отсечка.

3. **Механизмы в коде, которые зависят от карты, а не от эталона.** Это гипотезы для проверки на боксе, не факты:
   - **(а) Группа порога растра** (`expds/pix_e1g1.py:242`, `assign_groups`):
     - тип выбирается по подстроке «цвет» в имени файла (`cv` / `gr`);
     - плотность — по числу кандидатов на растре (< 300 → `lo`, иначе `hi`);
     - честные пороги по фолдам: `cvhi` ≈ 0,40, `grhi` ≈ 0,27, `cvlo` ≈ 0,034, `grlo` ≈ 0,011 (`orch/bot-W4/runs/ht_CetO3_Sr8G_noTerFl_L_E1.log`). На границе в 300 кандидатов порог прыгает в 10–25 раз.
     - на тесте у каждого участка MagGr ровно один файл, а не пара «серый + цвет», как в трейне. Как там названы файлы, неизвестно.
   - **(б) Нормировка по растру** c′ = 0,9·c^A·(c/q₉₀)^(1−A). На карте, где настоящих находок много, высок q₉₀, и уверенность настоящих находок падает ниже порога.
   - **(в) Масштаб.** Рабочий шаг 0,1 м получается только целым прореживанием (`expds/pix_clean.py:228`): карта грубее 0,1 м остаётся в родном шаге, а признаки считаются в пикселях (σ 1–8 px). В трейне шаг карт MagGr от 0,022 до 0,18 м (`notes/geo_probe_train.json`).
   - **Проверка на боксе.** На честном OOF 18 участков сравнить полноту находок E1_G1 по группам `cv`/`gr` × `lo`/`hi` и по шагу карты. Отдельно — «тестовый» режим: один файл на участок.
   - Исправление — только через PREREG, honest и LB-пробу. Финал идёт на v2, так что это нужно лишь для чистого запасного варианта.

4. **D-FINE на новых участках — шум, теперь в целых числах.**
   - Спутник v4 против v2: +16 TP и +686 FP. Добавленная выдача попадает в **2,3 %** случаев, безубыточность базы — 8,9 %.
   - Ортофото v4: 2 ложных и ни одного попадания (порог 0,484).
   - Правило `docs/LB_DROP_20261104.md` «спутник — только при new34 ≥ +0,002 и LB-пробе» подтверждается.

5. **Геофизика публичного теста — это две карты MagGr, один участок EtGr и одна карта TerFl.**
   - Геофизика — половина эталонов теста (1441 из 2907). P/R геофизики на LB — выборка из двух карт находок.
   - Перенос выводов о геофизике с LB на закрытую выборку несёт большой разброс. Насколько велика закрытая выборка, неизвестно (`notes/public_val_2026-10-22.json`, conclusions).

## Что из этого следует для финала (ТР п. 8.3.2, 8.3.5, 8.3.6)

- На закрытой выборке засчитываются **две** успешные попытки, в рейтинг идёт лучшая. Если команда сама не загрузит финальную версию, платформа возьмёт две версии с лучшим публичным баллом: сейчас это v2 (0,41238) и E1_G1 (0,38988).
- Второй слот имеет смысл отдать варианту, который может обойти v2, а не варианту, который заведомо ниже. Лучшая попытка из двух выигрывает только на той, что выше.
- **Кандидат на второй слот — v2 + FR1h** (`submission_fr1h_on_eb268d6.zip`, sha256 `fe8d60b9…`, `orch/reports_v2_fr1h_candidate_2026-11-01.md`):
  - честно +0,0041 к A, P 0,999, повреждённые курганы +0,0107;
  - но new34 только +0,0004, а это правка спутника;
  - на LB не отправлялся ни разу.
- По правилу из `docs/LB_DROP_20261104.md` его нужно проверить LB-пробой до 14.11: в сутки разрешены 3 успешные посылки (ТР п. 7.5.6).
  - FR1h ≥ v2 → второй слот финала — FR1h.
  - FR1h ниже v2 → второй слот — E1_G1 (чистая, без риска EN).
- Отдельных ставок на геофизику по публичному баллу не делать: в публичном тесте две карты.
