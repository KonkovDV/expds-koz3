## 0. Терминология (важно для комплаенса)
* **P-retrain** (то, что делает `koz3-w4-pixgbm-s3` и прежний `koz3-bot6-pixgbm-cleanroom`): переобучение
  `models/pixgbm/all/{poly,finds}.txt` скриптом `scripts/pixgbm_retrain_cleanroom.py` на признаках
  **текущего** `expds/geo_pixgbm.py` (вендорится в ядро). Это **воспроизводимость моделей, НЕ clean room**
  в смысле `docs/PIXGBM_DECISION.md`: линия модуля остаётся производной от EN; вариант B, а не C.
* **P-clean**: чистая перепись по `docs/PIXGBM_DECISION.md` (автор спецификации ≠ исполнитель, без доступа
  к `geo_pixgbm.py`, `geo_finds_gbm.py`, веткам `bot3-*`). Кода пока нет.

## 2. Приёмка P-retrain (воспроизводимость, без табло)
sha256 новых моделей = `MODELS_NOT_IN_GIT.md` **или** метрик-фолбэк: max|Δp| ≤ 1e-4 на фиксированной
матрице, или совпадают feature_name() и num_trees(). Иначе — FAIL, модели не подменяются.
Результат P-retrain не даёт права сдавать с pix без декларации (вариант B).

## 3. Приёмка P-clean (как в PIXGBM_DECISION + гейт W4)
Пары A = v3 без pix (`[geophys.pixgbm] enabled=false`) vs C = v3 + перепись; honest-10, семейные фолды, seeds 0..2.
Принять, если ΔC−A ≥ +0,009 (=+0,012−0,003), бутстреп P(C>A) ≥ 0,95, ≥ 4/5 фолдов в плюс, срезы «34 новых» и
«без лидара» не хуже −0,003, mock_val ≤ v2+60 с, check_submission OK. Гейт W4 (Δ≥+0,003, P≥0,9) — нижняя
граница, действует более строгое. Иначе — вариант A.
