## 2. Сбой мозаики оставлял курганы одной сети

`expds/pipeline.py`, ветка «мозаика не собралась, курганы с грубой сетки». Успешный проход по мозаике копит `fresh += …` по всем сетям. Запасной проход по грубой сетке делал `fresh = found` и затирал предыдущую сеть.

На одной сети `li` в `default.toml` присваивание и накопление совпадают: в списке те же курганы. На двух сетях при упавшей мозаике оставалась только последняя. Теперь обе (`test_failed_mosaic_keeps_kurgans_from_every_network`). Успешная мозаика идёт прежней веткой `fresh +=`.

## 3. Умершее чтение окон останавливало весь снимок

`[speed] read_ahead` входит в `PROVEN` и включён, даже когда `[speed] enabled = false` (`expds/speed.py`, `use_fast`). Следующее окно читает второй дескриптор GDAL.

Если второй дескриптор не открывался, фоновый поток клал исключение и конец очереди. Цикл окон ловил `StopIteration` как ошибку окна. После трёх таких ошибок файл останавливался, хотя дескриптор в главном потоке уже был открыт и читался. Объектов с этого снимка не было.

Теперь окно, которое фон не отдал, читается уже открытым дескриптором. Живой фон по-прежнему отдаёт свои пиксели: тест с массивом девяток на нулевом снимке видит девятки, а не нули файла. Мёртвый фон на снимке из троек видит тройки во всех четырёх окнах, а не ноль вызовов сети.
