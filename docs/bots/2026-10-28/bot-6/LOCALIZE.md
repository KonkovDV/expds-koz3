## 3. Привязка к рельефу (Li) — отрицательно
- **Li_c / Li_ch / Li_g / Li_i — это RGB-визуализации, а не DEM** (uint8; c — гипсометрия синий→красный с перескоком в пурпурный, g/i — отмывка).
  - Высоту восстанавливал по оттенку, затем LRM (минус гаусс σ 4/8 м).
  - Проверка на 354 эталонных курганах (`val/val_summary.txt`): центр сдвигался на 1,5 м в случайную сторону, затем привязывался.
  - Ошибка после привязки p50 1,77–2,60 м против 1,50 м до; ближе к эталону стали только 31–42 %.
  - Из точного центра эталона привязка уводит на p50 1,88–2,94 м.
  - Многие повреждённые курганы не видны как холм (`viz/gt_snap.png`).
- **DEM из LAZ** (точки земли, класс 2; сетка 0,25 м; LRM σ 4/8 м; те же PK1/PK2/CM): тоже отрицательно (`work/localize/dem/snap_dem.log`).
  - Выборка: 400 эталонов, 29 участков; LAZ есть у всех; в оценку вошли окна с ≥60 % заполненных ячеек, n = 104.
  - Из сдвига 1,5 м ошибка после привязки p50: CM 1,86–1,99 м, PK 2,26–2,52 м; ближе к эталону стали 30–40 %.
  - Санити: в центре эталона LRM выше, чем в точке со сдвигом 1,5 м, лишь у 59 % (p50 0,143 против 0,131 м).
  - Вывод: вершина холма не совпадает с центром разметки, сигнала на 1–2 м нет.
  - Оговорка: точки земли редкие, ячейки 0,25 м заполнены на p50 42 %. На ПК можно повторить с полным DEM пайплайна (`expds/lidar.py build_dem`), но ожидать прибавки не от чего.
- Ae/Or (яркость/градиент): в кэше нет растровых окон кандидатов. Если привязка к рельефу по LAZ не помогает курганам, то для Ae/Or ожидать её нечего. Отдельная команда для ПК ниже.

## 4. Форма finds_points / object_poly
- object_poly:
  - микрокруг −0,00016 (до и после порога);
  - консенсус C2/C3 — 0;
  - форма не мешает матчингу. Промахи — это центр вне эталона (детекция/смещение), а не покрытие.
- finds_points:
  - точка с допуском 2 м, форма не участвует;
  - консенсус C3 −0,0007 (−24 TP): соседние находки — разные объекты, усреднять нельзя.
