## Находки (с путями)

### 1. Что делает канал
- `repo/configs/default.toml`: `[models] ae = {path="models/ae_fort_mask_r18.pt", classes=["fortifikatsii"]}` — это единственная сеть ae. Пороги `[thresholds_by_markup.ae]`: fortifikatsii 0,998215. Пороги курганов 0,99053 / 0,802255 относятся только к копиям лидара.
- `repo/expds/pipeline.py` `optical_feats` (стр. 467–490): прогоняет ae / sp_or / or через `_raster_with_model`. `lidar_feats` (стр. 386–391) вызывает `fusion.li_to_ae` **только если у участка есть LAS**.
- `repo/expds/fusion.py` `li_to_ae`: копирует курганы сети лидара в слой ae там, где снимок не пуст. Копии мозаики и грубой сетки идут в группу `li_ae` с порогом «целых» 1,000001, то есть «целые» копии мозаики выключены. Сдвиг снимка (`register`) выключен.

### 2. Откуда «0,09 / 0,013»
- `repo/docs/LB_LOG.md`: аэрофото 0,090909 / 0,013333. Число одинаковое во всех посылках с 24.10. Самый мелкий целый набор, который с ним сходится: 75 эталонов, 1 попадание, 20 ложных (`repo/docs/AI_WORK_PLAN_2026-10-25.md` §2.10; `repo/docs/AUDIT_2026-10-24.md`). Кратный набор тоже возможен.
- `repo/materials/compute_metrics.py` `_build_by_data_type` — блок справочный: TP и FN считаются по слою эталона, FP — по слою предсказания. На `final_score` он не влияет. Балл идёт только через F1 классов, а сопоставление общее по всем слоям. Значит, курган ae, найденный лидаром или спутником, в «аэрофото» засчитывается.
