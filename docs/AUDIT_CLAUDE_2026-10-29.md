## 0. Вердикт

1. **Призы решает не этот LB.** Квалификационный рейтинг на призы не влияет. Финал — 17–19.11 на закрытой выборке, которая не пересекается с публичной; число попыток ограничено. Если финальную версию не загрузить, берутся две лучшие версии квалификации (`docs/background/KOZ3_ORGANIZER_MATERIALS_2026-10-21.md` §2). Поэтому 0,616 у Nikolove — ориентир, а не цель. Цель — балл на скрытых данных, и выбирать его надо по честному табло и переносимости по типам данных, а не по публичной дельте.
2. **Корень проблемы — ранжирование и калибровка, а не поиск** (§1). Кандидаты уже покрывают уровень 0,66: оракул-реранкер по нашим кандидатам даёт 0,658 (bot-4 GAP §4). Идеальные пороги дают только 0,367. Самый наглядный случай — ConvNeXt лидара бота 9. На своих участках он сильнее нашей лидарной ветки (0,713 против 0,476 по эталону li, в выборке). Честную приёмку он не прошёл из-за **разной калибровки на разных участках**: лучший порог повреждённых 0,329 на одной семье и 0,064 на другой.
3. **0,61 к 11.11 по измеренному не достигается.** Для 0,616 средний F1 по семи классам должен быть около 0,62 — это 1,93 раза к честной базе A по каждому классу. Измерено +0,014 (v2) и около +0,04 (v3). Реалистичный коридор — 0,42–0,48 по шкале LB. Выше — только если сработает лидар на ConvNeXt с калибровкой по участку (§1.3).
4. **Данные прошлого этапа брать нельзя.** Организаторы: датасет КОЗ №2 «будет полностью синхронизирован с текущим и удалён, в обучение не брать» (там же, §3.2). Family (№4) и GigaFlex (№5) — победители этапа «Сканирование», их преимущество — модели и опыт, а не доступ к данным. Пункт T2 прошлой версии аудита (письмо о данных этапа) снят.
5. **v2 загрузить всё равно стоит.** Посылка даёт точные P/R по типам данных на публичной выборке. Геофизика там — recall 0,26 против 0,72 у соперника, и только площадка покажет, закрывает ли PIXGBM этот разрыв (§3.3). Число посылок квалификации ограничено (до 10 всего, до 3 в сутки), и они не влияют на призы. Тратить их на диагностику — правильное использование.

## 1. Корень проблемы

### 1.1 Где теряются очки

Честная A по классам (bot-4 GAP, точный пересчёт): FN-потери 0,525, FP-потери 0,083. Мы теряем почти всё на **пропусках**, а не на лишних срабатываниях. При этом кандидаты для этих пропусков у нас есть:

| | балл |
|---|---|
| честная A | 0,3195 |
| идеальные пороги групп (по эталону) | 0,3674 |
| оракул-реранкер по **нашим** кандидатам | **0,6576** |
| полнота кандидатов (доля эталона с кандидатом) | курганы 0,65–0,67, находки 0,60 |

Между «идеальными порогами» и «оракулом» лежат +0,29. Это качество уверенности: верный кандидат и шум получают одинаковые баллы. Сильнее всего это видно у курганов вне лидара. Спутник: повреждённые — эталонов 1087, найдено 139, кандидаты есть у 744. Аэрофото: эталонов 1162, найдено 166, кандидаты есть у 522.

### 1.2 Почему уверенность плохо ранжирует: калибровка по участкам

- Порог в сдаче — один на группу (`thresholds_by_markup`). Шкала сети на разных участках разная: плотность LAS, растительность, контраст снимка, Солнце.
- Прямое доказательство (bot-9 `CONVNEXT.md` §2–3). У одной и той же модели ConvNeXt лучший порог повреждённых 0,329 на одной семье и 0,064 на другой. Честный порог одной семьи на другой дал 613 TP / 5142 FP против 372 / 678 у базы, и модель отклонена с Δ −0,0105. В выборке тот же ConvNeXt на этих участках — 0,713 против 0,476 у нашей ветки.
- Косвенно — пороги 0,99–1,000001 у половины групп конфига (`li_ae`, `li_dev`, `ae`, `li_coarse`…). Совместный перебор порогов выключает группы, шкалу которых нельзя перенести между участками.
- Геофизика эту болезнь уже лечит рангом внутри карты (`geophys.rank_within_source`): растяжение контраста карт несопоставимо. Оптика и лидар — нет.

### 1.3 Что с этим делать

1. **ConvNeXt лидара — на все 44 семьи** (бот 9: `c3sc-f23`, `c3-f4`). Мерить как **замену** группы `li` для курганов (`oof_transform.py merge-classes`), а не добавку к ней. Добавка удваивает FP в одних и тех же местах.
2. **Калибровка по участку без эталона** — `[post.site_calibration]` (§6.5). Режимы rank / quantile / mix внутри (участок, группа, класс), пороги групп — заново. Мерить на `li_cnx` и на текущих `li`, `sp_or`, `sp_focal`.
3. **Реранкер второго уровня** по кандидатам курганов: уверенности всех сетей в точке, соседство (§6.2), «внутри городища» (§6.1), положение в кадре (§6.4), физика рельефа. Его надо учить только с калибровкой по участку и честно по семьям. `rerank_all` без неё не прошёл (LOFO −0,012).

### 3.3 Почему v2 нужно загрузить сегодня

- Публичная геофизика — 1441 эталон, больше половины публичного эталона. Наш классический детектор отдал 570 объектов: подпись «мало выдачи», а не «плохие пороги». Классика давит соседние пики в радиусе 2 м. В плотных полях находок (на трейне до 173 на 1000 м², средний шаг около 1,2 м) это режет recall. У PIXGBM радиус подавления 0,75 м.
- Честный прирост PIXGBM S (+0,012) мерен на трейне, где классика и так видит 64–85 % находок. На публичной выборке узкое место другое, поэтому прирост там может быть больше. Это гипотеза. Проверить её может только площадка, и одна посылка даёт точные P/R по типам данных.
- Правило «LB отклоняет ветку только при Δ < −0,012» сохраняется. По одной посылке пороги не двигать.

### 4.5 География и правила разметки

- Курганы стоят могильниками (у соперника ближайший сосед: медиана 8,1 м на лидаре, 41,5 м на спутнике). Отсюда **множитель соседства** (§6.2).
- Правило организаторов: насыпи внутри городищ курганами не размечаются. На трейне внутри городищ 7 из 974 курганов. У соперника кандидаты внутри лидарных городищ — курганы в 2 % случаев против 45 % снаружи. Отсюда **маска городищ** (§6.1).
- Рамка сцены: метки есть только около памятника, и спутниковая сцена центрирована на нём. Framing prior у соперника на спутнике: 0,279 → 0,297. **Реализовано за флагом** (§6.4).

## 6. Что реализовано в этой ветке

### 6.1 `[post] kurgans_outside_hillforts` — правило «насыпь внутри городища»

`expds/post.py: kurgans_outside_hillforts`. Курган, чья внутренняя точка внутри выданного городища того же участка, убирается. Шаг идёт после порогов и после twins, до микрокругов. Городища вне 500–400 000 м² маской не служат: ядро-круг или ложная гигантская маска. Параметры: `min_gor_conf`, `gor_groups`, `groups`, `buffer_m`.

```bash
python scripts/oof_transform.py gormask --src КУРГАНЫ_OOF.geojson --hillforts ГОРОДИЩА_OOF.geojson \
    --taus notes/<табло>.json --out work/kur_gormask.geojson
python scripts/scoreboard.py ... --replace <группы курганов>=work/kur_gormask.geojson --honest 10
```

### 6.2 `[post] kurgan_neighbour_prior` — соседство курганов

`expds/post.py: kurgan_neighbour_prior`. Уверенность × (0,5 + 0,5·clip(n/3, 0, 2)), где n — другие места курганов того же участка в радиусе 200 м, прошедшие порог своей группы. Оба класса в одной точке считаются одним местом. Шаг идёт **до порогов**, поэтому пороги групп `li`, `li_coarse`, `li_mosaic` после него нужно подобрать заново. `pipeline.output_floors` для этих групп опускает ранний пол курганов во столько же раз: иначе множитель мог бы только понижать уверенность. У соперника на лидаре nested 0,5765 → 0,5831; на LB recall +0,039 при precision −0,007.

```bash
python scripts/oof_transform.py neigh --src ЛИДАР_КУРГАНЫ_OOF.geojson --taus notes/<табло>.json \
    --out work/kur_neigh.geojson
python scripts/scoreboard.py ... --replace li=work/kur_neigh.geojson --honest 10   # пороги li — заново
```

Сетка: radius 100/200/400, k 2/3/5, floor 0,3/0,5/0,7. Выбор по nested, как в приёмке П1–П6.

### 6.4 `[post.frame_prior]` — приор кадра

`expds/post.py: scene_drel, annotate_scene_drel, frame_prior`; `pipeline._with_scene_drel`. Положение объекта в кадре d = max(|dx|/полуширина, |dy|/полувысота): 0 — центр, 1 — край. Из нескольких сцен, накрывающих объект, берётся меньшее d. Одно и то же правило на инференсе и в замере, имя снимка не нужно. За d0 = 0,5 уверенность линейно снижается до ×0,5 на краю. Шаг идёт до порогов.

```bash
python scripts/oof_transform.py frame --train F:/2/train-expds-3 --src SPOR_OOF.geojson --out work/sp_frame.geojson
python scripts/scoreboard.py ... --replace sp_or=work/sp_frame.geojson --honest 10   # пороги sp_* — заново
```

Сетка: d0 0,3/0,5/0,7; edge 0,3/0,5/0,7.

### 6.5 `[post.site_calibration]` — калибровка по участку

`expds/post.py: site_calibration`. Внутри (участок, группа, класс) по объектам с s ≥ floor (0,05):
- `rank` — доля не выше;
- `quantile` — s / q₀,₉₉;
- `mix` — s^0,5 · rank^0,5.

Участки с числом объектов меньше 30 не трогаются. Шаг идёт первым, до соседства и порогов. `pipeline.output_floors` опускает ранний пол калибруемых групп до floor, чтобы распределение участка на сдаче совпало с OOF.

```bash
python scripts/oof_transform.py calib --src LI_CNX_OOF.geojson --groups li_cnx --mode mix --out work/cnx_calib.geojson
python scripts/scoreboard.py ... --replace li=work/cnx_calib.geojson --honest 10
```

Порядок опытов: `li_cnx` после всех фолдов (rank, mix, quantile), затем текущие `li`, `sp_or`, `sp_focal`.

### 6.6 Время на закрытой выборке

`[time] optics_order = "small_first"` (`pipeline.optics_order`): проход оптики от дешёвых снимков к дорогим. `[time] optics_s_per_gb` — лидар перестаёт брать новые участки, если после него оптике не останется этого времени на ГБ снимков. Если времени хватает, выход тот же. Включать после прогона на копии публичной выборки и проверки, что файл ответа совпадает побайтно.
