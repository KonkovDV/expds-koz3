## 1. Цель
- Нужен заменяемый модуль геофизики, который по растрам карт методов выдаёт кандидатов двух классов:
  - `finds_points` (вес 10);
  - `object_poly` (вес 10).
- Задача модуля: поднять F1 этих классов в официальной метрике выше классической геофизики (`expds/geophys.py`).
- Ориентир — вклад прежней линии, ≈ +0.012 на honest-10 (global keep). Он служит только порогом приёмки, а не образцом реализации.

## 2. Входы
- **Участки:** геофизика есть только у регионов **200–217**.
  - 200–207: MagGr, 36 файлов, ≈ 0.99 ГиБ.
  - 208–217: EtGr, MagGr, TerFl, 266 файлов, ≈ 0.44 ГиБ.
  - На тесте могут быть другие участки с теми же типами.
- **Методы** (`markup_type`):
  - `maggr` — магнитометрия: серая или цветная карта, GeoTIFF, обычно EPSG:3857 или UTM;
  - `etgr` — электротомография: **каждый срез или профиль является отдельным эталоном (слоем)**, разъяснение 27.10;
  - `terfl` — термосъёмка.
- **Растр:** 1–4 канала, nodata или чёрный фон за пределами съёмки; шаг пикселя от ~0.02 до ~0.5 м.
  - Для EPSG:3857 метры проекции ≠ метры на земле (масштаб 1/cos φ).
  - Перевод в метры на земле включается отдельным флагом G (`ground_metres`, bot-3 de1edc9) и **в этой задаче не смешивается**.
  - CRS берётся из файла, иначе из `UTM.json` участка (`fallback_crs`).
- **Маски:** граница съёмки и шумовые маски из участка. Их применяет вызывающий код, как в классике (`apply_masks`).
- **Обучение:** только трейн КОЗ-3, разметка `*_object_poly*`, `*_finds_points*` в участках 200–217. Данные на S3 и в Kaggle-шардах `koz3-w4-geo-s000/s001` (см. PREREG W4 §1).
  - Запрещены данные КОЗ-2 «Сканирование» и внешние снимки.

## 3. Публичный интерфейс (контракт нашего пайплайна, менять нельзя)
Вызов делает `expds/pipeline.py` в блоке `[geophys.pixgbm]`, внутри try/except. Ошибка означает откат на классику.
- **`region_feats(reg, cfg, model_dir, guard=None, status=None) -> list[dict]`**
  - Возвращает кандидатов участка `reg` (объект региона пайплайна: имя, папки, файлы методов, CRS).
  - `status` — словарь, который модуль **заполняет**:
    - `done[(class_name, markup_type)]` — множество `source` (растров), где pix отработал;
    - `fell[(class_name, markup_type)]` — признак, что хотя бы на одном растре был откат.
  - Пайплайн по этим полям решает, где оставить классику (вариант S: `replace = true`).
- **`dedupe_union(old_feats, new_feats) -> list[dict]`**, для варианта H/U (`union_name_re`).
  - Возвращает те `new`, которые не дублируют `old`.
  - Дубль `object_poly`: центр нового лежит внутри старого полигона.
  - Дубль `finds_points`: расстояние ≤ 1 м.
  - Сравнивать **только тот же класс и тот же метод**. Для EtGr — только **тот же слой** (правила 29.10 п.4–5).
- **Формат каждого объекта** — тот же, что у классики:
  - `geom`: shapely-геометрия в CRS вывода пайплайна. Для точек это микрокруг, как в `geophys` (`circle_3857`).
  - `class_name` ∈ {`finds_points`, `object_poly`}.
  - `confidence` ∈ [0, 1], монотонна по качеству, сравнима между растрами (матчинг глобальный, сортировка по confidence).
  - `region_name`, `markup_type` (`maggr`/`etgr`/`terfl`).
  - `source`: имя файла растра, то есть слой.
  - `original_crs`.
  - Группа порогов: `threshold_group = "<метод>_pix"`.
- **Ключи конфигурации** `[geophys.pixgbm]` с теми же смыслами:
  - `enabled`, `model_dir`, `classes`, `replace`, `union_name_re`, `maps`;
  - `t_pix` — порог пикселя для object_poly;
  - `backend` (lightgbm; lleaves/treelite необязательны);
  - `budget_s`, `guard_reserve_s`, `procs`.
  - Новые ключи допустимы только с дефолтом, сохраняющим поведение.
- **Модели:** новые файлы в новой папке, например `models/pixgbm/clean/{poly,finds}.txt`. Старые `models/pixgbm/all` **не использовать**.
  - `check_submission.py` проверяет пары класс → файл модели: `object_poly` → poly (методы maggr/etgr/terfl), `finds_points` → finds (maggr).
  - Если имена файлов меняются, синхронно правится карта в check_submission, отдельным коммитом и с тестом.

## 4. Что считает метрика (цели, вытекающие из неё)
1. **Точки.** Попадание, если центроид предсказания в ≤ 2.0 м от GT-точки; one-to-one, жадно по confidence.
   - **Главная цель — точность координаты:** 809 FN честной базы имеют кандидата в 2–5 м.
   - Координата ставится в экстремум или центр аномалии, с субпиксельной оценкой.
2. **Плотность находок.** Доля GT-находок, у которых ближайший сосед < 2 м: 14–59 % по участкам (Гнёздово 59 %).
   - Подавление соседей радиусом 2 м выбросит до трети эталонов.
   - Радиус подавления нужно подбирать в диапазоне ~0.5–1.5 м на трейне, а не брать 2 м.
3. **Полигоны.** Попадание, если area(P∩G)/min(area) ≥ 0.5 **и** внутренняя точка P лежит внутри G.
   - GT object_poly мелкие: медиана etgr ~3 м², terfl ~19 м², maggr ~43 м².
   - Малый полигон или микрокруг внутри GT всегда даёт cov = 1.
   - **Цель — правильный центр, а не контур.** Допустимо выдавать компоненту как микрокруг радиусом `poly_peak_r_m` в её наиболее вероятной точке (режим выбирает `poly_mode`). Контур нужен, только если он не ухудшает F1.
   - BIoU, HD95 и PoLiS в балл не входят.
4. **Стоимость FP — 0.5.** Добавлять кандидата выгодно при шансе попадания p > F/(4−F); при F ≈ 0.13–0.55 это 3–16 %.
   - Пороги подбираются по этому правилу на OOF, а не «на глаз».
   - По каждому присутствующему классу всегда выдаётся хотя бы немного лучших кандидатов: пропуск класса стоит всего его веса.
5. **Дубли.**
   - Внутри одного метода и слоя один объект = один полигон или точка; дубли идут в FP.
   - Серая и цветная карта одного MagGr-участка — **один слой**: дедуп по 2 м уже делает пайплайн (`maps = "all"`).
   - Слои EtGr **не склеивать** между собой: каждый является отдельным эталоном.
6. **Матчинг глобальный по классу.** Confidence должна быть калибрована между участками и методами; разумно ранжирование по вероятности модели.

## 5. Разрешённые методы (общеизвестные; конкретный выбор за исполнителем)
- **Предобработка:**
  - устойчивая нормализация (медиана, MAD или квантили) на растр;
  - удаление тренда или фона (вычитание сглаженного фона, high-pass);
  - destriping по линиям съёмки;
  - перевод цветной карты в скаляр по шкале легенды или по яркости.
- **Попиксельные признаки** (учебники магниторазведки, scipy/skimage):
  - локальные статистики в окнах нескольких масштабов: среднее, std, квантили, min/max, ранг пикселя;
  - градиенты: модуль, направления, вторые производные, Лапласиан;
  - multi-scale фильтры: Гаусс, DoG, LoG, разность масштабов;
  - аналитический сигнал и его производные; upward continuation;
  - структурный тензор, Hessian (blob/ridge-меры);
  - локальная полярность, признак диполя (пара экстремумов разного знака рядом);
  - расстояние до края съёмки и nodata;
  - метаданные: метод, шаг пикселя, номер канала или слоя.
- **Классификатор:** LightGBM, бинарный, отдельно на класс (finds для maggr; poly для maggr/etgr/terfl, с методом как признаком или раздельно).
  - Пиксельное или окно-центрированное сэмплирование.
  - Баланс через взвешивание или undersampling фона, hard negatives.
  - Метка пикселя: внутри GT-полигона, или в радиусе r от GT-точки (r ≲ 1 м, с затуханием).
- **Декодирование:**
  - finds: локальные максимумы вероятности, подавление соседей радиусом R (R подбирается, см. §4.2), confidence = вероятность в пике или агрегат по окрестности;
  - object_poly: связные компоненты карты вероятности > `t_pix` с фильтром площади, выход — микрокруг в пике или упрощённый полигон (≤ 3000 вершин), confidence = максимум или среднее вероятности компоненты.
- Можно использовать numpy, scipy, scikit-image, lightgbm, rasterio, shapely, pyproj — то, что уже есть в `requirements*.txt`. **Новых зависимостей нет.**

## 6. Ресурсы и надёжность
- Срок фазы абсолютный: T0 + `budget_s` (сейчас 600 с; env `PIXGBM_BUDGET_S` важнее), а также ≤ `guard.left()` − `guard_reserve_s`.
- Перед каждым растром — прогноз времени по с/Мпикс.
- **Лестница деградации:** полный режим → только finds (maggr) → классика.
  - Ошибка на растре означает классику на этом растре и запись в `status["fell"]`.
  - Модуль **никогда** не бросает исключение наружу молча: каждый откат даёт строку в логе и счётчик в health.
- Параллелизм: `procs` процессов (0 → min(потоки, 4)). ОЗУ ≤ текущего: ≈ +0.35 ГБ на процесс, пик всего прогона ≤ 3 ГБ.
- Платформа: i9-14900KS 24 ядра, 96 ГБ, лимит 30 мин на весь сабмит. `mock_val` на ПК ≤ v2 + 60 с.
- Детерминизм: фиксированные seed, одинаковый выход при повторном запуске (sha выхода на опорном участке).
- **Строгий режим** `EXPDS_PIXGBM_STRICT=1`: отсутствие модуля или моделей даёт FAIL, а не тихий откат (LESSONS 3–4).

## 7. Обучение и протокол оценки
- **Фолды** — семейные, как в `scripts/oof_full.py` (`family_folds`, 10). Признаки и пороги подбираются **только внутри обучающих фолдов** (nested). Модель сдачи обучается на всём трейне.
- **Варианты:**
  - A = v3 с `[geophys.pixgbm] enabled = false`, то есть классика;
  - C = v3 + чистая перепись (вариант S, `replace = true`).

- **Срезы:** «34 новых» участка, «без лидара», по методам maggr/etgr/terfl, по классам.

## 8. Критерии приёмки (все обязательны)
1. ΔC−A ≥ **+0.009** (= +0.012 − 0.003); бутстреп по семьям P(C>A) ≥ **0.95**; ≥ 4/5 фолдов и seeds в плюс.
   - Гейт W4 (Δ ≥ +0.003, P ≥ 0.9) — нижняя граница; действует более строгий критерий из PREREG W4 §3.
2. Ни один срез («34 новых», «без лидара», каждый метод) не хуже −0.003. F1 `finds_points` и `object_poly` не ниже A.
3. `mock_val` на ПК ≤ v2 + 60 с; пик ОЗУ ≤ 3 ГБ; `check_submission` OK; zip сабмита содержит модуль и модели, sha записаны в манифест.
4. Тесты интерфейса:
   - контракт `region_feats`/`status`/`dedupe_union`;
   - EtGr-слои не склеиваются;
   - класс+метод в union;
   - откат по бюджету;
   - строгий режим.
   Старые `tests/test_geo_pixgbm_*` переписываются по этой спецификации, не по старому коду.
5. Документация:
   - отчёт исполнителя с заявлением и списком прочитанного;
   - запись в `docs/THIRD_PARTY.md` и `docs/AI_DECLARATION.md`: «чистая перепись по спецификации, автор ≠ исполнитель».
6. Если хоть один пункт не выполнен, финал собирается по варианту A (pix выключен).
