База сравнения: финальный `v3_on` @ b447649 (production replay 0,345439; база гейта 0,3337867).
Источники: EN (EhimenNathan_EXpedition @ d434e56, `configs/deployed_v20.json` и README/RESULTS),
ранний обзор `orch/COMPETITORS_2026-11-02.md`, `docs/COMPETITORS_2026-10-29.md`, оракульная таблица
`orch/bot-W3/runs/gap_breakdown.md` (стек 0,3220 → оракул 0,690).
Чистая комната (DOC-1): ниже только идеи и численные параметры. Код конкурентов не копируется ни в репозиторий, ни в спецификации.
W1 SATDET (Faster R-CNN, GPU elenakonkova, ETA 17:25 МСК) здесь не дублируется.

Исполнители: **2** = W1 (оптика и спутник), **3** = W2 (лидар), **4** = W3 (курганы и городища), **5** = W4 (гейт и гео).
Гейт для всех пунктов стандартный: honest-10 nested, bootstrap 2000, Δ ≥ 0,003, P ≥ порога Бонферрони;
полы классов kp/kt/gor −0,002, остальные −0,005; new34 ≥ 0 и nolidar ≥ 0.

## 0. Главный структурный вывод

Почти все спутниковые рычаги прошли по Δ и упали только на new34, причём на малую величину:

| Гейт | Δ | Что не прошло |
|---|---|---|
| R1 | +0,00995 | new34 −0,0023 |
| C1 | +0,0142 | new34 −0,0011, kt −0,0023 |
| SATREC2 A1 | +0,0135 | kt −0,0074 |
| SATDET track2 | — | new34 −0,0027 |

EN применяет те же приёмы **с ограничением по типу сцены**:
- framing prior действует только на больших сценах (≥ 1 Мпикс при 0,5 м);
- гейт городищ работает только на малых скриншотах;
- в «центральный приор на всех малых сценах» EN не поверил: рост давал один кластер (Кисловодск).

Отсюда правило для всех новых спецификаций: рычаг ограничивается по **размеру сцены и/или классу**. Первым делом нужна
диагностика Q0 (раздел 3): какие сцены и классы new34 дали минус в R1/C1/A1.

Попутная находка: `post.frame_prior` в v3_on настроен на группы sp_or/sp_focal/sp_focal2. Но `sp_dfine.drop_groups` эти группы
удаляет, поэтому в проде frame prior **не действует** (no-op). Это не ошибка сдачи, однако приор нужно заново привязать к `sp_dfine`.

## 3. Быстрые CPU-проверки на сегодня (в порядке запуска)

**Q0 — диагностика new34 (30 мин, бот 5 или 2, без гейта).**
Разложить минус new34 у R1, C1 и A1 по сценам, классам и размеру сцены (W·H в пикселях 0,5 м).
Вопрос: потери сидят в малых скриншотах или в больших сценах? От ответа зависят параметры Q2 и Q3.

**Q1 — arkh-only (бот 2).**
- Взять сохранённые OOF D-FINE (C1/A1).
- Применить центральный приор C1 **только к arkh** и nested-подбор порога arkh на сетке {0,15; 0,2; 0,25; 0,3; 0,373}.
- Остальные классы = v3_on бит-в-бит.
- В PREREG указать «класс выбран после C1/A1» и требовать P ≥ 0,99.

**Q2 — framing gate для больших сцен (бот 2).**
- Правило: для sp_dfine kp/kt/gor/arkh на сценах с W·H ≥ A удалить детекцию с d/half > x, если её score < t2.
- Nested-сетка: A ∈ {1; 2; 4} Мпикс (при 0,5 м), x ∈ {0,4; 0,5; 0,6}, t2 ∈ {0,35; 0,5; 0,7; 0,85}.
- Сцены меньше A не трогать.
- Отдельно привязать `post.frame_prior` к группе `sp_dfine` (сейчас в проде no-op).

**Q3 — gor-swap и привязка центра (бот 4).**
- Источник p_scene: OOF гор-гейта DINOv2-S (expds/gor_gate.py) по сцене.
- Только малые сцены (W·H нативно < 4 Мпикс; nested-сетка {2; 4; 8}).
- Если p ≥ g: выдать один gor с conf = p в центре сцены, привязанном к лучшему кандидату gor из sp_dfine со score ≥ s_min на расстоянии ≤ ρ·half от центра. Сетки: ρ ∈ {0,2; 0,35}, s_min ∈ {0,02; 0,1}.
- Если p < g: удалить gor детекторов в этой сцене. Сетка: g ∈ {0,05; 0,1; 0,2; 0,3}.
- Отдельно проверить LOFO по кластерам (Кисловодск ±), чтобы не повторить ловушку «один кластер».

**Q4 — близнецы li → sp_or (бот 4).**
- Для каждого лидарного kp/kt, у которого в регионе есть спутниковый слой, выдать копию в слой sp_or с conf = α·c.
- Ввести отдельную threshold_group `li_sp_twin`.
- Сетки: α ∈ {0,1; 0,3; 0,5; 1,0}, порог nested.
- Не выдавать копию, если в радиусе 8 м уже есть спутниковая детекция того же семейства.

**Q5 — спутниковый хедж курганов (бот 4).**
- Если у кандидата sp_dfine score второго класса курганов ≥ h, выдать второй класс со score = 0,99·score.
- Сетка: h ∈ {0,2; 0,3; 0,4; 0,5}, nested.
- Пол kt проверять строго.

**Q6 — кандидатный GBM находок (бот 5, CPU 4–8 ч, можно стартовать сегодня).**
- Кандидаты: локальные экстремумы |детрендированного поля| выше квантиля 0,88, минимальное расстояние 0,5 м.
- Дескрипторы, инвариантные к повороту: средние по кольцам r 0,2…1,2 м; max/min/размах; произведение противоположных секторов (знак диполя); асимметрия.
- Классификатор LightGBM (фолды по участкам). Точки r 0,5 м, порог nested.
- Варианты: замена пиксельного GBM находок или объединение с ним.

Каждый Q — отдельный PREREG и семейство гейта; Бонферрони учитывать по числу одновременных гейтов.
