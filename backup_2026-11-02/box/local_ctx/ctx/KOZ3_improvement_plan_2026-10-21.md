## Инструкция для ИИ-агента (прочитать первой)

1. **Единственный критерий — официальная метрика вне обучения.** Сопоставление идёт по «семьям» участков на полном стеке всех модальностей (задача P0-6). Изменение попадает в `configs/default.toml`, только если общий балл растёт и парный бутстреп по регионам (`python -m expds.metric compare`) даёт A > B не менее чем в 90 % выборок. Пиксельный F1, потеря и F1 одного слоя служат диагностикой, решения по ним не принимаются.
2. **Две оценки на каждый опыт:**
   - по всем 210 участкам трейна;
   - по 34 «новым» участкам с LAS, которые ближе всего к закрытой выборке.

   Если опыт улучшает первую оценку и портит вторую, он не принимается.
3. **Запрещено:**
   - код и веса других команд;
   - ultralytics/YOLO (AGPL), DINOv3 и веса SegFormer `mit_*` (см. раздел 8);
   - внешние данные под NC, SA или с запретом перераспространения;
   - выгрузка конкурсных данных в облако;
   - игра на багах метрики (зоны UTM);
   - зондирование эталона публичной выборки специальными посылками.
4. **Не повторять закрытые опыты** (раздел 9).
5. **Отчёт по каждой задаче:**
   - что изменено;
   - баллы до и после по обеим оценкам;
   - F1 и TP/FP по классам и группам порогов;
   - время инференса.

   Отчёт пишется в `docs/PLAN.md` или `docs/COMPETITOR_REVIEW.md`. Каждый инструмент ИИ записывается в `docs/AI_DECLARATION.md`.
6. **Каждую строку кода команда должна уметь объяснить на защите** (ТР 13.6.3). Простое решение лучше хитрого при равном балле.

## 1. Где сейчас балл

### 1.1. Метрика: что из неё следует для решений (проверено по коду `compute_metrics.py`)

- **F1 класса:** `2·TP / (2·TP + 0,5·FP + FN)`. Объект стоит выдавать, если вероятность попадания p > F/(4−F). При F = 0,3 это всего 0,081.
- **Если класс сейчас даёт F1 = 0, а в эталоне он есть, любой верный объект поднимает балл.** Это касается архитектуры.
- **Нормировка идёт только по классам, присутствующим в эталоне.** Ложные срабатывания по отсутствующему классу ничего не стоят, поэтому выгодно всегда выдавать все 7 классов.
- **Пул общий на все регионы, сопоставление жадное по `confidence`.** Каждый слой разметки (`li`, `ae`, `sp_or`) — отдельный эталонный объект. Два предсказания в одной точке с разными `markup_type` могут дать 2 TP.
- **Условие попадания в полигон:** внутренняя точка предсказания лежит в эталоне, а покрытие меньшей фигуры ≥ 0,5. Маленький круг в центре объекта — самый надёжный ответ, если центр внутри эталона.
- **Условие попадания в точку:** центроид не дальше 2 м.
- **`MultiPolygon` оценивается по самой большой части.** Уже учтено.
- **Платформенный `config.py` не лежит рядом с метрикой.** В ваших журналах есть предупреждение «config.py недоступен — используются встроенные дефолты». Возьмите `config.py` из материалов платформы и пересчитайте один прогон (задача P0-4).

## 3. Стратегия

1. **Сначала страховка и посылка (P0).** Это дни, а не недели. Без неё любой прирост может не дойти до рейтинга.
2. **Ставка №1: курганы там, где нет LAS (P1-1).** Это крупнейшая по весу непокрытая часть эталона. Публикации 2026 года показывают, что детекторы курганов на снимках высокого разрешения работают, если задача поставлена как детекция с фокальной потерей (раздел 10). F1 0,05 у вас означает проблему в данных или в постановке, а не потолок модальности. Поэтому первым идёт аудит разметки (P0-7).
3. **Ставка №2: выжать лидар.**
   - Полная сетка для всех облаков (P1-2).
   - Устойчивость к новым участкам (P2-1).
   - Копии в ae с подтверждением по снимку (P1-3).
4. **Ставка №3: дешёвые классы.** Архитектура с нуля, городища на крупном масштабе, фортификации (P2-2, P2-3).
5. **Публичный рейтинг — это измерительный прибор (раздел 6).** Каждый день 2–3 посылки, A/B только по структурным вопросам.

## 4. Задачи

Формат: цель → шаги → приёмка → время и GPU. Задачи P0 — до 24.10.

### P0-1. Запасной путь лидара при любом сбое модели

- **Где:** `expds/pipeline.py::lidar_feats`.
- **Шаги:**
  1. Загрузку сегментаторов обернуть в `try`. При исключении записать в `seg_cache["li"] = []` и продолжить.
  2. Ветку модели обернуть в `try`. При исключении (включая `torch.cuda.OutOfMemoryError`) выполнить для этого LAS ту же ветку, что при `segs == []`: `candidates.detect` → `candidates.score(LightGBM)` → `threshold_group="li_cpu"`. DEM для запасного пути брать по `dem_params(None, cfg)`, если DEM модели не построен.
  3. На повторный OOM сначала уменьшить окно или батч инференса (`Segmenter.predict(batch=…)`), и только потом переходить на CPU-путь.
  4. Тот же принцип в `optical_feats`: сбой одной модели не должен останавливать остальные. Сейчас это так, проверить.
- **Приёмка:**
  - `pytest` в окружении без torch проходит (`test_main_writes_valid_geojson` даёт курганы);
  - новый тест: битый `.pt` → курганы из LightGBM с `threshold_group="li_cpu"`.
- **Время:** 2–3 часа, без GPU.

### P0-2. Сторож времени и промежуточная запись

- **Шаги:**
  1. Новый модуль `expds/watchdog.py`: поток-демон с дедлайном `PLATFORM_LIMIT_S − 180 с` от старта процесса (часы — `time.monotonic()` в `main.py`).
  2. По срабатыванию сторож снимает копию накопленного `feats` и прогоняет его через ту же постобработку (`only_known_classes → apply_thresholds → merge_within_markup → finalize → cap_features`). Затем атомарно пишет файл (`tmp` + `os.replace`) и вызывает `os._exit(0)`.
  3. Контрольные записи после фазы геофизики и после фазы лидара — той же функцией.
  4. `DemPrefetch` работает на `ThreadPoolExecutor`, а он при обычном выходе ждёт свои задачи. Поэтому выход сторожа — только через `os._exit(0)`, без `sys.exit`.
  5. Время постобработки 20 000 объектов замерить. Если оно больше 30 с, в сторожевой записи пропускать `merge_within_markup` для групп, где больше N объектов.
- **Приёмка:** тест с `budget_s=3` и искусственно медленным шагом: файл валиден, код возврата 0, объекты фазы геофизики в нём есть.
- **Время:** 3–4 часа.

     - TP и выданные объекты по группам порогов (как `score_coarse.py`);
     - балл по подмножествам: все, 49 с LAS, 34 новых, участки без LAS;
     - 90 % интервал бутстрепа по регионам.
  4. Кэшировать предсказания ветвей, чтобы замена одной ветви пересчитывалась за минуты.
- **Приёмка:** число совпадает с `metric score` на том же файле, расхождение 0. Записать базовую линию в `docs/PLAN.md`.
- **Время:** 1 день; GPU — только если какой-то ветви нет в кэше.

### P0-7. Аудит разметки курганов на sp_or и ae (до любых новых сетей)

- **Цель:** понять, почему детектор снимка даёт F1 0,05 при 169 почти-попаданиях.
- **Шаги (скрипт `analysis/audit_optical_gt.py`, без GPU):**
  1. **Привязка между слоями.** На участках с двумя слоями разметки курганов (li + ae, li + sp_or, ae + sp_or) взять для каждого объекта ближайший объект другого слоя в радиусе 40 м. Построить вектор сдвига (dx, dy), гистограмму и медиану по участку. Если медиана по участку ≠ 0 и разброс мал, это систематический сдвиг привязки. Счётчик «пар ближе 5 м» в `gt_stats` такие пары не видит.
  2. **Сдвиг предсказаний.** Для почти-попаданий сети спутника (центр ближе 20 м, но не засчитан) построить (dx, dy) до центра эталона по участкам. Если вектор устойчив по участку, это привязка; если направления случайны, это локализация.
  3. **Геометрия эталона.** Для полигонов курганов sp_or и ae посчитать:
     - площадь;
     - округлость 4πS/P²;
     - число пиков рельефа внутри (на участках с LAS).

     Полигоны с ≥ 2 пиками или округлостью < 0,5 — это «группы» или иная разметка. Доля таких объектов решает, как ставить цель обучения.
  4. **Снимок под эталоном.** 50 случайных курганов sp_or и 50 случайных ae вырезать окнами 80×80 м с контуром эталона. Сохранить контактный лист (PNG) для глаз команды. Это внутренний файл, в репозиторий не коммитить.
- **Решения по итогам:**
  - Если сдвиг систематический внутри участка, но разный между участками, на инференсе его не знать. Тогда цель — центр насыпи на снимке, а не эталон (для обучения перенести эталон на снимок: сдвиг по участку из п. 2).
  - Если сдвиг между ae и li устойчив, копии li → ae сдвигать нельзя. Но можно на инференсе совмещать снимок ae с рельефом по курганам (взаимная корреляция карт вероятностей) — это идея P1-3b.
  - Если много групповых полигонов, учить центры групп с кругом меньше группы или выдавать центр самого крупного пика.
- **Время:** 0,5–1 день.

### P1-1. Курганы по снимку v2 (sp_or + ae без LAS)

Основа — уже начатая карта центров (`--target centers`), с исправлениями. Сейчас F1 пиков 0,265 на 6-й эпохе и затем падение. Это типичная картина нестабильного обучения на малых данных.

- **Шаги:**
  1. **Потеря.** Вместо BCE с `pos_weight = 20` — фокальная потеря CenterNet со штрафом у пика (Law & Deng, 2018; Zhou et al., 2019): α = 2, β = 4, нормировка на число объектов. Ширину гауссианы брать от размера объекта, σ ≈ r/3 по площади эталона, а не фиксированные 4 м.
  2. **Стабильность:**
     - EMA весов (decay 0,999);
     - косинусный LR с прогревом 1 эпоха;
     - lr 3e-4 для энкодера и 1e-3 для головы;
     - выбор чекпойнта по **объектному** F1 официальной метрики на проверочной «семье», а не по пиксельному.
  3. **Данные:**
     - Учить ae и sp_or одной моделью: перевод в оттенки серого с вероятностью 0,5 для sp_or (ae чёрно-белые) плюс канал-признак модальности. Это вдвое больше курганов: 2249 повреждённых и 794 целых в эталоне.
     - Шаг 1 м, тайл 256 (256 м контекста). Насыпь sp_or в среднем около 25 м.
     - Аугментации: яркость, контраст, гамма, шум, размытие и резкость, JPEG, масштаб 0,75–1,33 (разные поставщики снимков), 8 поворотов и отражений.
  4. **Трудные негативы.** Второй раунд, как на лидаре: топ ложных пиков на пустых участках (Кисловодск, Гочево и подобные) не ближе 30 м к эталону.
  5. **Выход.** Круг радиусом 3–4 м в пике (а не 6 м): при центре внутри эталона покрытие меньшей фигуры гарантированно ≥ 0,5. Выдавать оба класса с их вероятностями, как у лидара.
  6. **Энкодер.** ResNet34 (`smp`). Если останется ночь — ConvNeXt-Nano через `timm` (MIT). На 4 ГБ: тайл 256, батч 8, FP32.
  7. **Вариант Б, если центры не дают F1 слоя ≥ 0,15 после двух ночей.** Двухступенчатая схема:
     - кандидаты — уже существующие пятна 8/16/28 м (66 из 88 курганов в топ-1000) плюс пики карты центров;
     - оценщик — ResNet18 на вырезке 96×96 м вокруг кандидата вместо LightGBM на 7 числах;
     - обучать по «семьям».
- **Приёмка:**
  - F1 слоя sp_or + ae (повреждённые) ≥ 0,20 вне обучения;
  - P0-6: общий балл ↑ ≥ 0,01 с A > B ≥ 90 %;
  - отдельно проверить, что на участках с LAS балл не падает: пороги групп `sp_or` и `ae` подбираются совместно (`metric` joint per-group).
- **GPU:** 3–4 ночи (5 фолдов × 30 эпох около 35 минут на 1 м, по `docs/SKLAD.md`; с ResNet34 и тайлом 256 — около 2–3 часов на прогон).

|---|---|---|

## 10. OSINT и мировая практика: что нового на 21.10

**Конкурс:**
- Канал @expds: загрузка до 11.11, результаты квалификации до 14.11. Финальные испытания 17–19.11, экспертиза и верификация 24.11–09.12, итоги до 25.12.
- Лимит — 10 попыток, из них 3 успешные в сутки.
- Материалы можно менять не позднее чем за 10 дней до конца квалификации (пост 98). По ТР метрику и выборки — до 10 дней до начала финала.
- Публичного рейтинга в канале нет.

**Конкуренты:**
- Новых открытых репозиториев КОЗ №3 с баллами на настоящих данных не найдено.
- Образ `evgps/ds3v2-koz3` продолжает обновляться (свежий тег — около трёх дней назад, около 4,6 ГБ). По разбору 19.10 это стек YOLO.
- Публичный каркас `yakirill99/ds-expedition` не публикует балл на настоящих данных.
- Вывод не меняется: большинство идёт через YOLO и маски. Ваш задел — центр и пик вместо маски, проверка по «семьям», раздельные слои.

**Курганы на снимках высокого разрешения** (Chen et al., Remote Sensing 18(2):185, 2026; Алтай, GF-2 0,8 м):
- 1087 чипов с курганами (столько же, сколько у вас повреждённых на sp_or).
- Детектор DDQ на Swin-L из MMDetection.
- Фокальная потеря дала самый большой прирост; трансформерные и более крупные энкодеры — тоже.
- Авторы сознательно ставят полноту выше точности.
- Ошибки: мелкие насыпи в несколько пикселей, низкий контраст, сезонная растительность, разница дат снимков.
- Для P1-1 из этого берём две вещи: фокальную потерю и постановку «детекция объекта, а не маска».

**Городища на лидаре** (обзор поиска городищ по Европе, JCAA):
- Классификатор ConvNeXt на окнах 768 м по сырому DEM.
- Перенос между странами слабый (F1 0,12–0,21), после дообучения на местных негативах — 0,34–0,38.
- Ложные срабатывания: тропы, обрывы, мысы, террасы, карьеры, замки.
- Для P2-2 из этого берём большой контекст и негативы того же рельефа.

**Многомасштабный рельеф для курганов** (Guyot et al., Remote Sensing 10(2):225, 2018):
- Отклонение от среднего на трёх масштабах разделяет курганы на мезо- и макромасштабе, но не на микро.
- Это совпадает с вашими `lrm_s` и `lrm_l` и поддерживает `lrm_xl` для городищ.

**Не удалось прочитать:**
- ScienceDirect (статья о курганах ямной культуры в Болгарии, 2025) — сайт запрещает автоматическое чтение;
- PDF Frontiers о машинном обучении на магнитке, 2025 — ошибка загрузки.

Выводы выше на них не опираются.
