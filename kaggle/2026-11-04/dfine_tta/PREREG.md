# PREREG: TTA D-FINE на спутнике — 8 видов D4 (04.11.2026, до запуска ядра и любого замера)

Коммит этого файла — метка времени. Ядро `dmitrijkv/koz3-dfine-tta` запускается после коммита.

## Зачем

Задание к 0,61 (`docs/plans/PROMPT_TO_061_20261103.md` §4): TTA спутника и D-FINE ни разу не мерились на честном гейте. Флаг `[orsp_tta]` есть в коде (`expds/orsp_tta.py`: виды `d4`/`d8`, слияние `nms`/`wbf`), но выключен с пометкой «не оценено». Сейчас D-FINE смотрит на окно в двух видах: как есть и с горизонтальным отражением (`flip_tta`). Обучался он на всех 8 элементах группы D4 (отражение + поворот на 90°·k, `jitter()` бота 5), поэтому остальные 6 видов для модели не новые. Запас времени сабмита ≈ 8× (3:48 из 30:00).

## Что считается

Модель — та же, что дала `sp_dfine` в базе гейта: веса фолдов f0–f4 из вывода ядер `dmitrijkv/koz3-dfine-spor-full` (f1, f2, f4) и `dmitrijkv/koz3-dfine-spor-full-rest` (f0, f3). Растры SpOr — `dmitrijkv/koz3-w2-dfine2-raw-{a,b}`. Окна, порог 0,05, top-100, NMS 0,5 — как у исходного OOF. Каждый фолд считает только свои тестовые участки. Обучения нет.

На каждом окне один прогон 8 видов `(k·90°, отражение)`, и из них собираются три выхода:

- **V0** — виды `(0°, нет)` и `(0°, отражение)`, общий NMS 0,5. Это путь исходного OOF, повтор базы.
- **T8N** — все 8 видов; NMS по окнам внутри каждого вида, затем слияние видов NMS 0,5. Это `[orsp_tta] dfine_views="d8", dfine_fuse="nms"`, функции `expds/orsp_tta.py` (`invert_xyxy`, `fuse_views`).
- **T8W** — те же 8 видов, слияние WBF 0,55, уверенность = сумма / 8 (`dfine_fuse="wbf"`). **Только отчёт:** шкала уверенности другая, а полы группы `sp_dfine` в гейте — пороги архива, подобранные под старую шкалу. Честное сравнение WBF требует новых полов, а это отдельный PREREG.

## Гейт

Харнесс `w2_gate/dfine2_v3p/gate_dfine2_ctx_cls.py` (движок W4 `v3_gate_lib`, honest-10 по семьям, бутстрап 2000, seed 0), режим TTA. Круги строятся тем же путём, что `sp_dfine` в базе: радиус 4 м, слияние 4 м, max, одна модель, группа `sp_dfine`. Затем полы архива v3_on.

- **A′** = V3P_ctx, где `sp_dfine` взят из V0.
- **B** = V3P_ctx, где `sp_dfine` взят из T8N.
- Решающее сравнение: **B против A′** (одна модель, один код, разница только в видах).

PASS (все сразу): Δall ≥ +0,003, P(Δ>0) ≥ 0,95 (решающий вариант один), Δnew34 ≥ 0, Δnolidar ≥ 0, ΔF1 ≥ −0,002 для kp/kt/gor и ≥ −0,005 для arkh/fort (n_gt < 5 — исключение).

**Стоп до гейта:** упавший фолд, участок без выхода или V0 далеко от исходного OOF. Последнее значит: число эллипсов V0 по фолду отличается от `w4geo/spor_oof` больше чем на 2 % или |V3P(V0) − V3P(исходный)| > 0,002. В этих случаях ядро чинится и перезапускается, замер не делается.

Для отчёта (не решают): T8W против A′; A′ против V3P_ctx (насколько V0 повторяет базу).

## Если PASS

Это только кандидат. Дальше:

1. Сверить прод-путь `orsp_tta.detect_dfine` с ядром на 2–3 реальных растрах. Должны совпасть боксы до слияния.
2. Пороги `[thresholds_by_markup.sp_dfine]` подобрать заново по OOF T8N правилом метрики.
3. Перегейт поверх v4 (C1F зависит от уверенности `sp_dfine`).
4. Сборка, Kaggle-паритет и время на 4+ средах.

В `default.toml` до всего этого не идёт.

## Поправка 1 (04.11 13:40 МСК, после прогона v1, до любого замера гейта)

Ядро v1 (75 мин, 5/5 фолдов, без ошибок) остановлено стоп-правилом. Эллипсов V0 по фолдам относительно исходного OOF: f0 −0,5 %, f1 +0,1 %, **f2 +9,2 %**, f3 −0,2 %, f4 +0,04 %.

Причина. Зону UTM исходный OOF и прод берут из `UTM.json` участка. В датасетах `koz3-w2-dfine2-raw-{a,b}` этого файла нет, и ядро вычисляло зону по центру растра. У 47 участков из 132, лежащих у границы зон, зона получилась соседней: например, Курганы_* и Таш_Коро — EPSG:32643 вместо 32644. С другой зоной меняется сетка окон, а с ней и детекции.

Что изменено. Ядро v2 берёт зону каждого участка из исходного OOF (`original_crs`, по одной на участок, файл `region_crs.json`). Это та же зона, что из `UTM.json`. Больше ничего не меняется: ни виды, ни слияние, ни гейт, ни критерии, ни стоп-правило.

Чего не делалось. T8N и T8W прогона v1 гейтом не считались, их метрики и баллы не смотрелись. Сравнивалось только число эллипсов V0 с исходным OOF. Выход v1 не используется.

## Поправка 2 (04.11 14:55 МСК, после стоп-правила v2, до замера T8N/T8W)

Ядро v2 (зоны UTM из исходного OOF): 74 мин, 5/5 фолдов без ошибок. Санити:

- эллипсов V0 к исходному OOF: f0 −0,52 %, f1 +0,02 %, f2 +0,01 %, f3 +0,17 %, f4 +0,01 %. Допуск 2 % выполнен;
- участков без выхода — 0;
- **V3P(V0) − V3P(исходный) = −0,0022** при допуске 0,002 — стоп-правило сработало, гейт не считался (`results/gate_tta_v2.json`).

Разбор (до замера T8N). Сравнивались боксы V0 и исходного OOF: центры 0,24 м в медиане, p90 0,94 м; разница уверенности — медиана 0, больше 0,05 у 0,9 % боксов. Из боксов исходного OOF с уверенностью ≥ 0,3 у 17 нет пары V0 ближе 2 м: курганы повреждённые 9, городища 7, архитектура 1. Это разброс fp16 на GPU между прогонами и средами (другая версия ядра Kaggle). На CPU fp32 было то же: 0,11 м, 347 против 345 боксов. Ошибки конвейера здесь нет, это не случай зоны UTM из v1. Порог группы `sp_dfine` подбирается по немногим объектам эталона, поэтому такие сдвиги дают ±0,002 балла.

Вывод: **сам повторный прогон той же модели меняет V3P примерно на 0,002.** Это шум гейта для любой линии с перепрогоном детектора.

Что меняется. Абсолютное условие |V3P(V0) − V3P(исходный)| ≤ 0,002 заменяется на проверку конвейера по боксам: медиана сдвига центра ≤ 0,5 м, медиана разницы уверенности по модулю ≤ 0,001, без пропавших участков, число эллипсов по фолдам в пределах 2 %. V0 v2 эту проверку проходит.

Решающее сравнение остаётся тем же: T8N против V0 из того же прогона, это парное сравнение в одной численной среде. Критерии PASS не меняются: Δ ≥ +0,003, P ≥ 0,95, new34 ≥ 0, nolidar ≥ 0, полы классов. Для отчёта добавляется T8N против V3P_ctx на исходном OOF. Поправка записана после стоп-правила, но до любого замера T8N и T8W.
