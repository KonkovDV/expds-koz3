### 4.1. Параллель honest-10 гейтов

```
                    ┌─ CPU usertest1234 ── gate shard A (OOF filter + curves + τ sweep семей 1…k)
honest-10 plan ────┼─ CPU aaaadg4gg4g4g ── gate shard B (семьи k+1…m)
                    ├─ CPU aaaa0000004 ─── gate shard C / check_submission / scoreboard merge
                    ├─ GPU dmitrijkv ───── недостающие OOF-фолды / тяжёлый infer (если нужен новый OOF)
                    └─ GPU elenakonkova ── парный фолд / вторая модель (копии датасетов заранее!)
```

Конкретика:

1. **Один общий immutable dataset** `koz3-honest10-bundle` (на каждый CPU-акк — **своя копия** с тем же содержимым):  
   отфильтрованные OOF geojson (уже через `filter_geojson_conf`), GT, `compute_metrics.py`, снимок `expds/`+`materials/`, table.pkl/стек A, `EXPDS_GEOM_CACHE` seed (опц.).  
   Без S3/internet на CPU: всё только `/kaggle/input/...`.
2. **Шардирование гейтов** по независимым осям (не по одним и тем же τ на пересечении):  
   - шарды по **семьям участков** / markup_type / candidate-веткам;  
   - один акк = один kernel metadata + один output dataset;  
   - merge на боксе: `scoreboard`/`compare_candidates` читает 3 output dataset (как orch уже делает с kurgan-seeds).
3. **Аренды** как в `orch/COORD_LOG.md`: `slot:<user>/cpu` + `kernel:` + `dataset:` с TTL; watcher снимает ERROR.
4. **GPU**: только когда нужен **новый** OOF/веса; не жечь квоту на повторный honest-10 по готовому OOF.  
   Prep relief/LAS — отдельный notebook `koz3-*-prep`, выход — dataset; train-ядра монтируют prep, **не** пересобирают DEM.
5. **Кэш staging:**
   - Vendor wheel `expds_core` + pins в dataset `koz3-vendor-py312` → pip `--no-index` (экономия ~20–25 с/kernel).  
   - Prep snapshot (`cnx_relief` и т.п.) — версия в имени dataset; ядра ссылаются на фиксированный slug.  
   - На боксе/ПК: `EXPDS_DEM_DISK_CACHE=/dev/shm/expds_dem_cache` (или диск) + `EXPDS_GEOM_CACHE=/dev/shm/expds_utm_cache` + при больших стеках `EXPDS_RUST_MATCH=1`.  
   - Отфильтрованный OOF: файл `oof_conf020.geojson` рядом с сырьём; gate-скрипт предпочитает его, если mtime ≥ сырого.
