# PREREG_ORGATE_S — Gext-S: гейт arch + эмбеддинги DINOv2-S/reg (bot-6, 29.10, записан ДО любых расчётов эмбеддингов и оценок)

## Гипотеза
Эмбеддинги DINOv2-S/reg@112 (в ~4–5 раз дешевле B) дают гейту arch прирост, сопоставимый с Gext-B (k10 +0,001340 к G, ORGATE.md), и при этом укладываются в бюджет времени. Нулевая гипотеза: Gext-S ≤ G_noLAS.

## Варианты (код: work/orgate_s/gate_eval_s.py — копия work/orgate/gate_eval.py; меняются только пути вывода и добавленные варианты)
- **Gext_S (основной)**: признаки G_noLAS (X2 + 22 признака feats_gate.npz, БЕЗ правила LAS) + PCA(16) эмбеддингов DINOv2-S/reg, PCA обучается только на обучающих строках фолда (≤20 000), как в Gext. Строки ok=False → NaN. LightGBM с гиперпараметрами R/G (lr 0,05, 31 лист, min_data 100, ff/bf 0,8, λ2 1, монотонность conf/logit, 300 итераций), пороги — вложенно (sweep_groups на внутреннем 5-фолдовом OOF по семьям обучения).
- **G_noLAS (компаратор)**: считается в том же прогоне; парный бутстрэп Gext_S против G_noLAS.
- Диагностика (не для решения): Gext_S_rule (= Gext_S + правило LAS, паритет с Gext-B из ORGATE), только k10.
- Справочно: A (база honest-10 drop 0,314615), R (bot-10 counts_<layout>{_site}_full_orig.pkl), G и Gext-B — числа из ORGATE.md (res в work/orgate/res).

## Эмбеддинги
- Веса: официальные DINOv2 ViT-S/14 с регистрами (bot-4 для B использовал facebook/dinov2-with-registers-base → паритет: HF facebook/dinov2-with-registers-small, Apache-2.0). Источник и sha256 model.safetensors записываются в ORGATE_S.md.
- Кропы: конвейер bot-4 без изменений (bot-4/work/cropverif/embed.py, копия в work/orgate_s/embed_s.py; меняются только модель и пути): те же 30 688 кандидатов optical_pool_cands.npz, 0,5 м, 112 px, батч 32, нормализация ImageNet, признак = pooler(CLS) ‖ mean(patch) (768). Выход work/orgate_s/emb_dinov2s_reg_112.npz (stack_idx, ok, fill, emb float16, meta).

## Раскладки и статистика
honest-10 k10, LOFO, seed0–seed4 (random_family_folds), глобальный порог и --scope site (те же 7 раскладок). Бутстрэп 2000 по семьям, CI90 = [p5; p95], P = доля > 0. Отчёт: Δ vs A, Δ vs G_noLAS, Δ vs R, Δ без Елизаветинского.

## Правило решения
- П1: Δ(Gext_S − G_noLAS) ≥ 0,002 на k10 (для замены G_noLAS); П2: P ≥ 0,85; П3: LOFO > 0 и ≥ 4/5 семян > 0 (против G_noLAS); П4: тяжёлые классы не меняются (new34 = 0, меняется только arch); П5: если Δ < 0,006 → только пакет; П6: тот же режим unseen (drop), что у G/R.
- Если П1 не выполнен, но Δ > 0 на k10, LOFO и ≥ 4/5 семян, — «положительно, ниже порога П1», только пакет.
- Site: то же направление в ≥ 4/5 семян site.
- **Бюджет времени** (обязателен для любого принятия): t_test = N_test × (мс/кроп сеть + чтение), N_test = 7105 кропов (bot-4/work/cropverif/test_extrap.json; bot-4/CROPVERIF.md §3, оценка 739–1172 с для B). Проходит на CPU, если t_test ≤ 1200 − 639 = 561 с (639 с — текущий прогон по bot-4/CROPVERIF.md) при 2 потоках по замеру на боксе (худший из: замер без нагрузки — бенч, и боевой прогон под нагрузкой). Для 4090 — только оценка (не замер), критерий ≤ 30 мин всего.
