## Рецепт (по образцу s4: `/workspace/kpull/s4/koz3-gpu-s4.py`)
- Кропы ядро режет само из растров SpOr в S3, 8 участков параллельно; кэш участка удаляется после нарезки.
- Окно на местности: курган 64 м, городище 400 м. Для растров в 3857 масштаб поправляется на 1/cos(lat).
- Кроп хранится размером 120 px, на вход сети идёт 96 px:
  - в обучении — случайный кроп (джиттер ±12 px) плюс флипы и rot90;
  - на инференсе — центр кандидата плюс TTA из 4 флипов.
- Модель: torchvision ResNet18 (ImageNet, при ошибке скачивания — с нуля) с fc→1. Головы kurgan и gor — отдельные модели.
- Обучение: BCE с pos_weight ≤50, AdamW, OneCycle, AMP. Эпохи: kurgan 14, gor 30. Задачи (голова × фолд) раскладываются по 2 GPU в потоках.
- Выбор эпохи — по val-семье внутри обучающих фолдов: берётся семья с долей позитивов, ближайшей к 15 % (≤30 %). Если семей с позитивами меньше 3, берётся последняя эпоха.

### 2. Почему val ≫ test (фолд 4: 0,909 против 0,573)
Как формируется val (ядро, строки 218–225):
- одна семья из **обучающих** фолдов — та, у которой доля позитивов ближе всего к 15 % (≤30 %);
- из train эта семья исключена (`fam != valf`), а с тестом не пересекается (assert);
- в val попадают только кандидаты (kind = c);
- эпоха выбирается по максимуму val-AUC (строка 246).

**Утечка не найдена:**
- пересечений bbox участков между фолдами нет;
- кандидатов, у которых ближайший сосед из другого фолда ближе 400 м, — 0; ближе 2 км — 68 (`gap_diag.log`, spatial);
- дубли 957 povr/tselye лежат внутри одного участка.

Разрыв объясняется так:
1. **Val — одна и та же лёгкая семья, а эпоха выбирается по максимуму.** Для kurgan в фолдах 0, 3 и 4 val — Тыва: 816 кандидатов, 176 позитивов, prev 0,216 (в тестах prev 0,016–0,045). Максимум по 14 эпохам на одной семье завышен:
   - фолд 4: best 0,909, но среднее по эпохам 0,756, последняя эпоха 0,790;
   - фолд 2 (Курменту): 0,851 против среднего 0,757;
   - честная OOF-AUC верификатора на самой Тыве (модель фолда 1) — 0,716, conf на Тыве — 0,706.

   У gor val вырожден: Белая — 30 кандидатов и 2 позитива; Архангельское — 3 и 1; Костомаровское — 7 и 2. Отсюда best_val = 1,0 почти везде, а Архангельское в фолде 3 дало val_auc 0,0 на эпохе 0.
2. **Val меряет AUC внутри семьи, а тест — пул из 9–15 семей.** Средний p по семьям сильно разный, а большие семьи вообще без позитивов получают высокий p. Фолд 4:
   - Мостище: 2 179 кандидатов, 0 позитивов, p̄ = 0,708;
   - Архангельское: 1 763 кандидата, 0 позитивов, p̄ = 0,605;
   - Кисловодская: 4 637 кандидатов, 0 позитивов, p̄ = 0,499;
   - Кабардино (основные позитивы): p̄ = 0,419.

   Макро-AUC по семьям в фолде 4 — 0,650 против пула 0,573. У conf семейные средние ровнее (c̄ 0,10–0,12), поэтому пул её почти не портит.
3. **Настоящий провал на крупнейшей семье фолда 2.** Курганы: 13 097 из 16 353 кандидатов, 701 из 735 позитивов, AUC верификатора 0,520 против conf 0,722 (основные участки — 163_Курганы_34 и 158_Курганы_29). Кропы 64 м с SpOr там, видимо, неинформативны или не совпадают с объектом. Это не проверено: нужен просмотр кропов.
4. Фолд 3 (val Тыва 0,848, test 0,845) и фолд 1 (0,753 / 0,728) разрыва почти не дают. Значит, дело не в механической утечке, а в доменном сдвиге между семьями плюс оптимистичном выборе эпохи на одной семье.

### 3. Вердикт
- **kurgan: верификатор v1 не добавляет ничего к conf.**
  - Один он хуже conf: 0,586 против 0,725; по семьям Δ −0,13 [−0,21; 0,00].
  - Лучший стек (rank-avg в фолде) даёт 0,720 / AP 0,141 против conf 0,725 / 0,142, Δ −0,003 [−0,04; +0,05].
  - Logreg сводит вес верификатора почти к нулю.
  - **Отдавать OOF kurgan боту 10 под `scoreboard --honest 10` (П1–П5) не стоит**: ожидаемый Δ ≤ 0, а П1 (P ≥ 0,85) он не пройдёт.
- **gor: слабый сигнал есть, но на 18 позитивах.**
  - AUC 0,698 против 0,619; rank-avg в фолде — AP 0,140 против 0,054, Δ AUC +0,08 [+0,02; +0,14] по семьям.
  - Позитивы распределены по фолдам так: 2 / 2 / 9 / 5. Макро-AUC можно посчитать только по одной семье (Гочево: 0,618 против 0,497).
  - Отдать боту 10 можно только как дешёвую проверку с низким приоритетом: голова gor, скор = rank-avg(conf, p) внутри фолда/участка, базу не трогать. Ожидать, что П1–П5 пройдут, не стоит: 18 позитивов меньше MDE.
- **Если всё же отдавать**, p_verifier нельзя пулить между фолдами как есть: калибровка у пяти моделей разная. Использовать ранги внутри фолда или участка.

### 4. Что чинить (v2), по убыванию отдачи
1. **Выбор эпохи.** Вместо одной семьи взять val из 3–4 семей (или вложенный LOFO по обучающим фолдам) и выбирать по **пулу** val-семей, а не по внутрисемейной AUC. Ещё проще — фиксированное число эпох: argmax по kurgan = 4 / 1 / 8 / 2 / 3, медиана 3.
2. **Обучать остаток над conf**, а не голую классификацию:
