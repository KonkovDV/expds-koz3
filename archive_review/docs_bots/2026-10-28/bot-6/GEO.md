## 0. Что из этого реально дойдёт до LB (важно)
Разница keep-all против drop (+0,0186) — это **поправка учёта honest-10**, а не прирост сдачи. В сдаче порог etgr 0,096635 почти равен keep-all: к keep-all он даёт +0,00004 (`compare.log`), а terfl в сдаче идёт по порогу класса. Значит, honest-10 drop недооценивал текущую сдачу примерно на 0,019. Реальная Δ на LB может прийти только от:
- геометрии: круг 0,05 м даёт +0,0027 к исходной, оболочка +0,0017, обе по LOSO;
- pixgbm: от +0,0007 до +0,0028 к стеку, не значимо.

Против keep-all, то есть против текущей сдачи, совместный подбор даёт +0,0004, CI [−0,0044; +0,0044].

**Решение бота «1» (22:58):** круг 0,05 м НЕ берём. Он играет на нормировке покрытия по меньшей площади, а на приватной части это риск. Оболочка (+0,0017, P 0,998) уходит боту 10 на приёмку П1–П5 за флагом `[post] geo_convex_hull` (ветка bot6-geo, см. §6).

## 1. Почему honest-10 здесь слепой
Кандидаты и эталон etgr/terfl есть только на участках семьи Гнёздово (`extract.log`): etgr 403 кандидата на 212–217 и 658 GT; terfl 319 кандидатов и 177 GT только на 212 и 217. Семья целиком попадает в один фолд `family_folds(…,10)`, поэтому группа всегда «unseen».
- drop: 0,314615, object_poly tp 78 / fp 68.
- keep: 0,333245.

Мой счётчик воспроизводит оба числа точно (строки `A_drop` и `keep_all` в `geo_val.log`; совпадает с `base.log` и с keep у bot-3). Значит, протокол совместим с honest-10 бит в бит.

## 2. Протокол «honest-10 + LOSO для невиданных групп»
- Фолды те же (`base_honest.pkl['folds']`). Для групп, которые есть на обучающих участках, пороги подбираются штатно: `sweep_groups` на every−H.
- Для группы g, которой нет в every−H, порог каждого удержанного участка r подбирается `sweep_groups` на every−H ∪ (H∖{r}). Из подбора берётся только порог g.
- Утечка. Эталон самого r в подбор не входит никогда. Утекают только 1–3 скаляра (порог, геометрия, мин. площадь) с соседних участков той же семьи. Внутрисемейная корреляция остаётся: для etgr/terfl иного источника нет (семья одна). Поэтому ниже есть парное сравнение с keep-all, где подбора нет вовсе.
- Нет обучающих примеров группы (g есть только на r) → drop, как в honest-10. Для terfl это не срабатывает: 212 учится на 217 и наоборот.
- В режиме nested вариант геометрии и мин. площадь выбираются на том же обучающем множестве по F1 класса, затем подбирается порог.
- Остальные классы берутся из счётчиков базы honest-10 и не меняются. Попадания считаются как в `honest_counts`: жадно по всем кандидатам, официальный `_match_quality`.
- Бутстреп: единица — участок для Гнёздово 212–217, семья для остальных; 1000–2000 повторов.
  - Семейный бутстреп bot-10 здесь бесполезен: весь эффект в одной семье, и P(>0) = 0,643 = P(Гнёздово попала в выборку) во всех строках (`geo_val.log`).
  - Бутстреп по участкам внутри одной семьи занижает разброс. Это оговорка, а не доказательство.
